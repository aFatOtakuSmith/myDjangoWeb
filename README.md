# myDjangoWeb

## 项目概述

myDjangoWeb 是一个基于 Django 框架构建的模块化全栈 Web 平台。该系统集成了个人内容管理（博客、作品、动态）、高级多媒体交互（沉浸式音乐播放）、以及物联网（IoT）设备状态监控与指令下发功能。

项目采用前后端混合通信架构，通过合理的模块解耦与权限隔离设计，在保证数据传输实时性的同时，兼顾了企业级的系统安全标准。

---

## 核心功能模块

系统采用 Django App 架构进行业务拆分，主要包含以下模块：

*   **`core` (核心系统)**：承载全局首页、静态页面展示，以及基于 Django Auth 的统一用户鉴权与路由拦截。
*   **`blog` / `works` / `moments` (内容生态)**：提供文章发布、作品陈列及碎片化动态记录的内容管理系统。
*   **`music` (多媒体中心)**：实现音频流式播放、内嵌歌词解析同步、以及基于封面特征提取的动态 UI 主题。
*   **`todo` (效率管理)**：支持一次性待办与复杂周期性习惯的创建、打卡流转及动态漏签统计算法。
*   **`iot` (物联网中枢)**：负责硬件设备的数据采集落库与安全控制代理。

## 技术栈

### 后端架构
*   **Web 框架**：Python 3 / Django 5.2 (基于 MVT 架构，处理核心业务与 ORM 映射)
*   **数据库**：SQLite (关系型数据持久化)
*   **物联网协议**：`paho-mqtt` (与 MQTT Broker 建立双向通信)
*   **文件系统监控**：`Watchdog` (实现本地媒体目录变更的毫秒级事件捕获与自动入库)
*   **多媒体处理**：`Mutagen` (深度解析 MP3 ID3 标签，提取 USLT 歌词帧与 APIC 封面帧)
*   **运维部署**：Systemd (守护进程托管，保障服务高可用与开机自启)

### 前端交互
*   **基础构建**：原生 HTML5 / CSS3 / Vanilla JavaScript (零重型框架依赖，优化渲染性能)
*   **UI 框架**：Bootstrap 5 (全局响应式布局)
*   **实时通信**：`MQTT.js` (基于 WebSocket 的客户端长连接)
*   **视觉渲染**：`ColorThief` (基于 Canvas 的图片色彩量化提取，驱动 CSS 变量的动态渐变)

## 系统通信架构与安全设计

针对物联网模块，系统设计了 **“前端直连读取 + 后端代理写入”** 的混合安全模型。

### 1. 数据上报链路 (下位机 → 客户端网页)
*   **设备端**：下位机（如 ESP32 等）通过 MQTT 协议向指定 Topic 发布 JSON 格式的传感器数据。
*   **后台落库**：服务器后台常驻监听脚本（具备读写权限）订阅该 Topic，完成数据清洗后，通过 Django ORM 持久化至 SQLite。
*   **前端推流**：前端网页使用 **只读权限账号**，通过 WebSocket 直接连接 MQTT Broker 并订阅相关 Topic，实现 UI 数据的毫秒级无延迟更新。

### 2. 指令下发链路 (客户端网页 → 下位机)
*   **前端请求**：网页端不直接向 MQTT 下发指令，而是通过 `Fetch API` 向 Django 后端发起 HTTP POST 请求。
*   **安全代理**：Django 后端接收请求并完成用户鉴权后，由后端服务调用 `paho-mqtt`，使用 **高权限账号** 将控制指令发布至目标设备的 Topic。
*   **设备响应**：下位机接收指令并执行动作。

### 3. 架构安全审计
*   **ACL 权限隔离**：在 Mosquitto 消息代理层配置严格的 ACL (访问控制列表)。前端网页所使用的账号仅有 `myhome/device/+/data` 的读权限。即便前端代码被恶意破解，也无法绕过代理直接向硬件发送非法指令。
*   **并发控制与降级**：前端在处理音频流式加载、歌词高频定位、以及网络请求竞态（利用 `AbortController`）时，均设计了状态机隔离与兜底降级方案，避免资源阻塞与状态错乱。
